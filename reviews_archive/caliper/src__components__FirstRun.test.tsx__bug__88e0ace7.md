## Verdict (1-2 sentences)
The suite is green and most tests do assert real DOM/store behavior, but five spots lie about their protection: the "seats the deck LOCAL" test asserts a value its own `beforeEach` seeded (tautology), the "records done" counts can be satisfied by the harness's own stray deferred recorders, the "closes"/"holds the door open" claims are untestable because `onClose` is never spied, and the `:8188` assertion pins the unresolved module default so yesterday's `comfyPortNow()` change (c001de9) has zero coverage here.

## Bugs & vulnerabilities
**[HIGH] "Seats the deck LOCAL" asserts the value the test itself seeded - `line 87` + `line 266`** — What: `beforeEach` runs `useGenerateStore.setState({ mode: "local" })`, and the test then asserts `useGenerateStore.getState().mode === "local"` after clicking RENDER ON THIS MACHINE. Trigger: delete `setMode(path)` from `pick()` (FirstRun.tsx:184) — or break the button's `onClick` entirely — and the assertion still passes, because the store was already `"local"` before the click. Impact: the test's headline promise ("the local path seats the deck LOCAL") is completely unguarded; a regression that stops seating the mode ships green. Fix: seed `mode: "cloud"` in this test (or capture and compare a pre-click baseline) so the click's effect is the only thing that can produce `"local"`.

**[MEDIUM] `completeFirstRun` count assertions are satisfiable by stray deferred recorders from prior tests - `line 209` and `line 254`** — What: every `await unmount()` schedules the unmount-time `setTimeout(0) → completeFirstRun()` (FirstRun.tsx:60-62); that macrotask fires during the *next* test's `await mount()`, after `vi.clearAllMocks()` reset the count. Test 213 defends against exactly this with a post-mount delta baseline (lines 229-236, comment "a previous test's deferred unmount timer can fire into this one"), but tests at 204 and 250 assert bare `>= 1`. Trigger: delete `await completeFirstRun()` from `finish()` (line 121) or from `pick()` (line 178) — the stray record from the previous test's unmount still makes `mock.calls.length >= 1`. Impact: the "skip records done" and "the film path hands off" record-half claims can pass with the recording code deleted. Fix: capture `before = calls.length` after mount and assert a delta, as test 213 already does. CONFIRMED by mechanism trace (the file's own comment establishes the stray-timer behavior).

**[MEDIUM] "Holds the door open" / "and closes" are untestable as written - `line 246` (and the name at `line 204`)** — What: `mount()` passes `onClose={() => {}}`, so the wizard host never unmounts regardless of what `finish()` does; `expect(host.querySelector(".film-wizard")).toBeTruthy()` is guaranteed by the harness, not by the early-return (FirstRun.tsx:124). Likewise test 204's name says "records done **and closes**" but nothing asserts closing. Trigger: invert `finish()` so it calls `onClose()` even on record failure — both tests stay green. Impact: the failed-write-stays-open contract and the SKIP-closes contract are unprotected (class 1/10: vacuous assertion + action without asserted outcome). Fix: spy `onClose` (`vi.fn()`) and assert not-called after a failed record, called after a successful one.

**[MEDIUM] The `:8188` literal is satisfied by the unresolved module default, not by the c001de9 derivation - `line 97`** — What: the file neither mocks `../api/comfyOrigin` nor calls `resetComfyOrigin()`; nothing resolves `comfyOrigin`'s module state, so `comfyPortNow()` (comfyOrigin.ts:49) returns the `DEFAULT_COMFY_ORIGIN` port unconditionally. Trigger: revert c001de9 — hardcode `"backend answering on :8188"` back into FirstRun.tsx — the full suite stays green. Impact: the specific fix from yesterday (spoken port follows the configured origin; design-adversary 2026-09-17) has no regression coverage, and the module-level `resolved`/`flight` state is an unguarded leak seam if any future case in this file fetches `/api/comfy`. Fix: add a case that stubs `resolved` (via a fetched `/api/comfy` response or the seam) to a non-default port and asserts the spoken port follows. CONFIRMED by trace; unverified dynamically because proving it requires editing the file (forbidden).

**[LOW] The `humanBytes` mock re-implements byte formatting, and the one asserted value merely coincides - `line 11` + `line 197`** — What: the module mock formats as `` `${Math.round(n / 2**20)} MB` `` while production `humanBytes` (install/client.ts:50-60) walks B/KB/MB/GB with one-decimal display. For `100 * 2**20` both happen to yield "100 MB", but e.g. the fixture's `totalBytes: 12 * 2**30` would read "12288 MB" through the mock vs "12.0 GB" in production. Trigger/Impact: any future assertion on the total-bytes half of the row (line 270's ` / ${humanBytes(totalBytes)}`) would pin the mock's algorithm, not the product's (class 9). Fix: don't mock `humanBytes` (it's pure and side-effect-free — import the real one in the factory).

## Missing safeguards
- `beforeEach` resets `uiStore`/`generateStore` but never `useRoutesStore` — test 162 mutates `profile` to `"cloud-only"` and sets `loadedOnce`; nothing currently reads it afterwards, but it is live cross-test state in the file.
- `mount()` never removes the host `div` from `document.body` — 14 orphan divs accumulate per run (harmless only because every assertion is host-scoped).
- No coverage of `watch()`'s "the server forgot the job" path (`installStatus` returning `job: null` mid-watch → `load()` re-probe + honest status, FirstRun.tsx:75-81) or the 400-iteration give-up ceiling.
- No assertion that `pick()` routes to the Generate surface (`setSurface("generate")`, FirstRun.tsx:185).
- The unmount recorder's swallowed failure (`completeFirstRun().catch(() => {})`, FirstRun.tsx:61) and `pick()`'s fire-and-forget record are trusted, never exercised with a rejection.
- Test 184's `watch` loop is left parked on a disposed fake timer after `vi.useRealTimers()` — harmless only because `dead.current` gates it; a floating promise by construction.
