### Review

## Verdict
XSS-safe: there is no `dangerouslySetInnerHTML`; every brain-authored byte travels through React text nodes or the escaped `alt` attribute, and at the only production mount all image srcs are funneled through `resolveImage` into the local `/view` endpoint (MediaView.tsx:34), so LLM-injected `javascript:`/external-URL markdown cannot execute or phone out. The block parser correctly round-trips the storyboard grammar (join regex matches the emitter's line, `kf_NN.png` resolves against the film folder, the `---` separator rows of script.md tables are skipped). What remains is a set of edge-case parser/render traps and latent state hazards — nothing on the common path is wrong.

## Bugs & vulnerabilities
- **[LOW] Table parser promotes the first data row to header when the separator row is missing or consumed** - `lines 40, 44` — CONFIRMED logic, edge trigger. What: any contiguous `|`-prefixed block whose first surviving row becomes `rows[0]` is treated as `head`. Trigger: an LLM-authored table that omits the `---` row (generators emit one — vite.film.ts:520-521 — so this needs a hand-edited or brain-drifted doc), or a table whose first row is all-empty cells, which line 40 silently swallows as a separator (every cell `=== ""`), promoting the second row to header. Impact: the owner reads column data as column labels — a mislabeled approval/summary table. Fix: only treat `rows[0]` as head when a separator row was actually present and skipped; render separator-less tables headerless.
- **[LOW] Any line beginning `→` or `->` is promoted to a join divider** - `lines 21, 32-33` — CONFIRMED logic; PLAUSIBLE trigger. What: `JOIN = /^(?:→|->)\s*(.+)$/` fires on any such line in ANY doc class. Trigger: lyrics or script text containing an arrow line ("-> chorus", "→ repeat") — lyrics ship verbatim from user text or brain narration joins (vite.film.ts:1710-1711). Impact: an ordinary lyric line renders as a centered divider between rules — content garbled into chrome. Fix: tighten the pattern to the storyboard's own emitted shape (`^→ JOINS PANEL \d+ BY …`) and keep the loose form behind the storyboard doc class only.
- **[LOW] Pending frame conflates "not produced yet" with "failed to load"** - `lines 72-78` — CONFIRMED logic, edge trigger. What: any `onError` — including a transient view-endpoint failure or ComfyUI being down while the film IS produced — renders "panel pending - the frame renders at produce". Impact: a false claim about a paid artifact, which collides with the repo's standing truthfulness rule (status text must report what the server says). Fix: distinguish the two (e.g., only show the pending copy when the doc is known pre-PRODUCE; on produced boards show a retryable load-failed state).
- **[LOW] `inline()` false emphasis on stray asterisk pairs** - `lines 61-63` — CONFIRMED logic, edge trigger. What: the split regex `\*[^*]+\*` italicizes the span between any two single asterisks — "timed at 5 * 3 * 4 reps" or a prompt containing two footnote stars renders `* 3 *` as emphasized text, mangling prompt text the owner is judging. Impact: cosmetic misrendering inside approval docs. Fix: require word-boundary-ish context for single-asterisk emphasis (e.g., `\*(\S[^*]*\S?)\*` plus a check the opener isn't preceded by whitespace) or only honor `**bold**`/`` `code` ``.
- **[LOW] PanelImage's `broken` flag never resets when `src` changes** - `lines 69-79` — CONFIRMED as a latent hazard (not currently reachable). What: `useState(false)` for `broken` persists across prop changes because the component is keyed by block index (`key={i}`, line 104) and nothing resets state on `url` change; once `broken` is true it stays true even if the new doc's image loads fine. Trigger trace: currently REFUTED as live — MediaView nulls `doc` between fetches (MediaView.tsx:15, `setDoc(null)`), and `doc === null` renders the loading `<p>` instead of DocView (MediaView.tsx:32), force-remounting every PanelImage on every document swap. It becomes a real stale-pending bug the moment any parent keeps DocView mounted across doc changes (the exported component invites reuse). Fix: `<img key={url} ...>` or `useEffect(() => setBroken(false), [url])` inside PanelImage — cheap insurance at the component that owns the state.
- **[LOW] Paragraph-per-line parsing: no soft-wrap joining** - `line 54` — CONFIRMED, cosmetic. What: each non-empty line becomes its own `<p>`, so a wrapped paragraph (brain-authored scripts/lyrics rendered at 720px with hard per-line spacing) displays with a blank gap mid-sentence. Fix: accumulate consecutive plain lines into one paragraph block.

## Missing safeguards
- No empty-document state: `doc=""` (or a doc of only blank lines) renders a blank pane — the frontend protocol wants empty states to be invitations with a next click; show a "no words in this document" state.
- `resolveImage` is optional and a raw-src fallback renders whatever URL the markdown carries — safe at the current mount (always resolved locally), but a future consumer mounting DocView without a resolver turns LLM-authored `![x](https://…)` into an outbound request, violating the localhost-only network policy. Consider defaulting to a safe placeholder when no resolver is supplied.
- The feeding layer's failures are invisible through DocView: MediaView swallows fetch errors into `setDoc(null)` (MediaView.tsx:19-21), so a failed read shows "reading the words…" forever, and its effect keys only on `[filename, subfolder]` (MediaView.tsx:23), so a same-named rewritten file is never refetched while open. DocView itself has no error or stale presentation — worth an error prop or a keyed remount at the feed.
- No `overflow-wrap`/`min-w-0` on paragraphs, headings, or cells: a long unbroken token (URL, hash, model name) stretches the 720px column and forces horizontal scrolling of the whole pane rather than wrapping — the known retired-design garbling class; one Tailwind class (`break-words`) on the container closes it.
