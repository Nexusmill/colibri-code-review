### Review

## Verdict
Correctly avoids see.mjs's known stale-media trap: it waits on the live `done · seed N` status chip (DeckControls.tsx:173, fed by the non-persisted queueStore — verified no `persist`/localStorage in src/stores/queueStore.ts), so a reload-restored previous render cannot fake completion, and the `.pane-render` media query (lines 79-84) is informational only. The CLEAR_PARAMS settle-then-clear-then-reload discipline (lines 15-25) matches the harness's learned race handling. The real defects are in failure handling: nothing after the queue click can fail the run (exit code stays 0), the library check cannot attribute this run's output, any thrown error leaks a tab into the persistent browser, and CLEAR_PARAMS clears less state than the known-good twin.

## Bugs & vulnerabilities

- **[MEDIUM] Job failure, timeout, and a refused queue click never fail the run — exit code is always 0** - `lines 65-77, 95-98` — CONFIRMED. What: (a) `queued === false` (button missing/disabled — e.g., singleGuard while a previous render still runs) is only logged, then the script waits the full 10 minutes anyway; (b) the wait loop captures `error[^\n]*` into `lastStatus` (line 72) but never breaks on it — a failed render dead-waits all 300 iterations; (c) loop exhaustion prints `job finished: false` and proceeds to screenshot and a clean exit 0. Impact: the tool's entire purpose is verification, yet every failure mode after the defaults gate produces a success-shaped outcome (screenshot saved, exit 0). The defaults-refusal path (line 53) proves the tool knows how to fail (`process.exit(2)`) — the discipline just stops there. Fix: `if (!queued) { ...exit(3) }`, break the loop on the error alternative, and `if (!done) { ...exit(4) }` before the library check.

- **[MEDIUM] The Library check cannot attribute THIS render — any earlier LTX mp4 satisfies it** - `lines 87-93` — CONFIRMED. What: `libHit = txt.includes(".mp4") && txt.includes("LTX")` against the library overlay, whose provenance is server-side and cumulative (the harness's own `provenance-shared` test, ui-harness.mjs lines 703-727: wipe all browser storage and "the library still knows every render the machine ever made"). This machine has LTX history, and the driven profile is shared with the harness. Trigger: the render fails or times out (see previous finding) — the old entries still match, `libHit` prints true, and the stated purpose ("confirm the render reached the Library with bundle attribution", header line 4) reads as satisfied. Fix: snapshot `/api/provenance` (or the mp4 name list) before queueing and require a NEW entry whose prompt/params match this run.

- **[MEDIUM] No try/finally — any thrown error leaks a tab into the persistent Edge** - whole file; cleanup only at `lines 53, 97-98` — CONFIRMED. What: `page.close()`/`browser.disconnect()` run on the happy path and the defaults-refusal path, but not on exceptions — `page.waitForSelector` timing out (line 34, 15 s), `goto` failure, or any evaluate error bypasses both. The browser is deliberately long-lived ("Start the driven Edge once (it survives between runs)" — see.mjs header lines 4-9) and shared with ui-harness.mjs, so each failed run accumulates another loaded-app tab (memory creep, and stacked tabs in later screenshots). Fix: wrap lines 34-96 in `try { ... } finally { await page.close(); await browser.disconnect() }`.

- **[MEDIUM] CLEAR_PARAMS clears less persisted state than the known-good twin — stale windows/cloud-mode survive into the run** - `line 21` vs `ui-harness.mjs` `resetSession` (lines 126-131: removes `caliper.bundles-ui`, `caliper.screen`, `caliper.ui`) and `gotoApp` (lines 97-107: also removes `caliper.generate`, `caliper.wizard-draft`, with a recovery reload for a persisted cloud-mode source) — CONFIRMED gap; consequence PLAUSIBLE. What: this script removes only `caliper.bundles-ui`. The header's "fresh .see-profile, so no persisted params" (line 2) is stale for the CLEAR_PARAMS mode — that mode exists precisely because the profile isn't fresh, and it is the SAME profile the harness writes (`--user-data-dir=E:/AI/Caliper/.see-profile`, ui-harness.mjs line 36). Trigger: a harness run (or a crashed one) leaves persisted `caliper.screen` windows or a cloud-mode `caliper.generate` selection behind. Impact: an open library/asset window garbles the verification screenshot (the artifact), and a persisted cloud-mode source selection means no `button[title="Switch bundle"]` ever renders — the script dies at line 34 into the orphan-tab path above. Fix: clear the same key set as `resetSession`, and adopt the local-arrived recovery reload.

- **[LOW] Bundle selection is a silent no-op on miss — wrong bundle queues with no gate outside the defaults check** - `lines 37-41` — CONFIRMED gap. `opt?.click()` does nothing if the flyout hadn't opened within the fixed 500 ms or the label drifted; there is no post-selection verification. The harness twin verifies (`if (!picker.includes(name)) throw` — ui-harness.mjs lines 142-143). In the documented CLEAR_PARAMS/EXPECT_DEFAULTS mode the stepper gate catches it, but with a misleading message ("steppers do not show the new defaults" when the real fault is the flyout); run bare (no env vars) and there is no gate at all — the wrong bundle renders for 10 minutes. Fix: after the click, assert the Switch-bundle button's text contains "LTX-2.3-Distilled" as the harness does.

- **[LOW] Screenshot path is CWD-relative, unconditionally overwrites, and the log names no location** - `line 95` — CONFIRMED. `path: "see-shot-ui720p.png"` resolves against wherever `node` was invoked, not the repo — run from another directory and the artifact (plus the "saved:" line) points nowhere findable; each run also destroys the previous capture with no timestamp. see.mjs at least parameterizes the output path (argv[2]). Gitignored (`see-shot*.png`), so no repo pollution. Fix: resolve against `import.meta.url` (`new URL("../see-shot-ui720p.png", import.meta.url)` — the pattern rebaseline.mjs uses for its reads) or accept an argv path.

- **[LOW] Hard-coded expected defaults and an undocumented env contract** - `lines 50-51` vs header `lines 1-5` — CONFIRMED. `["1280", "720", "241"]` duplicates bundles.json ground truth (verified current: width 1280, height 720, frames 241); when file defaults legitimately change, the script REFUSES on a healthy app. The harness reads `/api/bundles` as ground truth (`servedBundles`, ui-harness.mjs line 156). Also, neither `CLEAR_PARAMS` nor `EXPECT_DEFAULTS` is documented in the header — the usage contract lives only in inline comments. Acceptable for a dated one-shot, but cheap to fix: read the served defaults, document both env vars.

## Missing safeguards
- No guard against the stale-dist trap the harness doctrine names ("tests whatever serves :4173"): the defaults check incidentally catches an old build in the gated modes, but the script never records WHICH build served the page — a version stamp in the log would make a capture self-attesting. (The preview server serving stale dist is a documented false-bug source in AGENTS.md.)
- The media check (lines 79-84) can read reload-restored media from a prior session — harmless now because it is informational only, but it should stay that way; gating anything on `.pane-render img/video` presence would reintroduce see.mjs's stale-media trap.
- `puppeteer.connect` failure (Edge not started) exits via raw stack with no pointer to the launch command — see.mjs's header carries the msedge invocation; this file references it only obliquely ("see tools/see.mjs header").
