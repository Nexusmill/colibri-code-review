## Bugs & vulnerabilities
- **[MEDIUM] Multi-line anchor is embedded raw into the one-line-per-field doc grammar** - `line 33` — CONFIRMED. What: `**Anchor** (the frozen continuity block) - ${sb.anchor}` assumes `anchor` is single-line, but the anchor is COMPILED code-side as `world.characters/sets.map(...).join("\n")` (src/film/worldmodel.ts:161), injected by `withWorldAnchor` (worldmodel.ts:166-168) which runs before `writeStoryboardFile` (vite.film.ts:1687 → 1713). Trigger: every world-anchored draft — deterministic, not LLM-dependent. Impact: the anchor block's continuation lines (one per character, one per SET) are re-parsed by DocView as unlabeled standalone paragraphs, violating the emitter's own declared grammar ("this emitter is the single source of storyboard.md's shape", lines 6-7); if any brain-authored world field (a character name like "- Ana", a material containing a leading `|`, or an internal newline that `validateWorld`'s `str()` trim doesn't remove) puts a grammar metacharacter at a line start, that line renders as a list item / table / divider inside the owner's approval artifact. Fix: at emit time, split the anchor and render it as a labeled list (`**Anchor** (the frozen continuity block):` followed by one `- line` per entry), or collapse internal whitespace (`replace(/\s*\n+\s*/g, " ")`) like every other field should be.
- **[MEDIUM] Brain-authored newlines/metacharacters in shot fields splice forged blocks into the approval doc** - `lines 30-51` — PLAUSIBLE (no upstream guard exists). What: `beat`, `dialogue`, `narration`, `boardPrompt`, `shootPrompt`, `title`, `styleBible`, `scorePrompt` are interpolated raw. The only sanitizer upstream is `validateStoryboard` (src/film/autopilot.ts:263-268), which `.trim()`s the ENDS — internal `\n` survives untouched. Trigger: the brain returns a JSON string field containing a newline (realistic for music-video dialogue) or a line-start metacharacter after an embedded newline. Impact: a dialogue containing `\n## x` forges a `## PANEL`-class heading mid-panel (desyncing the panel count the owner counts and the ui-harness "storyboard-compound-doc" check keys on); `\n→ ...` forges a join divider; `\n| a | b |` forges a table; a beat beginning `![](...)` forges a frame. The doc is the approval artifact — structural forgery misrepresents what the owner is approving. Fix: since this file is the declared single source of the doc shape, normalize here — `const one = (s: string) => s.replace(/\s*\n+\s*/g, " ")` applied to every interpolated field (plus the anchor in the finding above); alternatively reject embedded newlines in `validateStoryboard`.
- **[LOW] cutIn is never validated against the transition canon; unknown values half-render** - `lines 24-26, 51` — CONFIRMED behavior (severity low because tested-intended for the undefined case). What: `joinArrow` lowercases and falls back to `→ CUT` for anything outside the seven canon values, while line 51 still prints the raw value: cutIn `"crossfade"` renders `→ JOINS PANEL 2 BY CROSSFADE → CUT`. `validateStoryboard` (autopilot.ts:268) only lowercases — a typo'd canon value (`"dissolv"`, `"Action!"`) sails through and the owner reads a made-up transition name next to a generic cut glyph — shown-vs-sent enum drift. Fix: validate `cutIn` against the canon list in `validateStoryboard` (the list already exists as the doc comment at autopilot.ts:76-78) and drop-to-undefined non-members, so the honest `UNDECLARED` path (already tested) carries them.

## Missing safeguards
- Mixed numbering sources in adjacent lines: the panel head uses array position (`PANEL ${i+1}`, line 41) while the frame filename uses the field (`s.index`, line 43). The invariant `index === i` is guaranteed only by `validateStoryboard` (autopilot.ts:282, `index: i`) and mirrored at PRODUCE (vite.film.ts:694/713) — the emitter's type (`StoryboardShot.index: number`) permits divergence, and any future caller that splices/regroups shots silently mismatches panel numbers to frame files. Derive both from one source inside the loop or assert `s.index === i`.
- The on-disk `storyboard.md` is never re-emitted after post-draft mutations: the redraft apply path (vite.film.ts:1938-1944) rewrites `boardPrompt`/`shootPrompt`/`cutIn` in the autopilot record but never calls `writeStoryboardFile` — the doc the owner can still open from STORYBOARDS artifacts shows pre-redraft words. Cross-file divergence; fix belongs in vite.film.ts (one `writeStoryboardFile` call in the apply block).
- No guard for an empty `shots` array in the pure emitter (upstream validates non-empty at autopilot.ts:258, but the function is exported and test-called directly; it would emit a header-only doc rather than signal misuse).
