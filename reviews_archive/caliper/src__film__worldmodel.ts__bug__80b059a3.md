## Bugs & vulnerabilities

- **[HIGH] Window redraft silently truncates the anchor out of shot prompts — breaking this module's core invariant** - `line 144` (docstring) vs autopilot.ts:569 and vite.film.ts:1933 — CONFIRMED. What: the file's contract says the compiled anchor "is what every boardPrompt and shootPrompt carries verbatim (manifesto clause 1)". The checkpoint window-redraft path rewrites shot prompts: `parseRedraft` (autopilot.ts:569) hard-slices each to `slice(0, 600)` and the apply block (vite.film.ts:1933-1940) patches `shot.boardPrompt`/`shot.shootPrompt` with NO anchor-coverage check and NO re-run of `judgeStoryboard` (the adversary's 60%-token continuity check ran only at draft time, on the pre-redraft storyboard). Trigger: owner rejects a window (the designed QA loop), brain returns rewritten prompts; buildRedraftPrompt itself instructs "copy CHARACTER-FOR-CHARACTER into every boardPrompt and shootPrompt" (autopilot.ts:542) — for a world-built film, one character sheet (~450+ chars) + set line (~250+ chars) + action already exceeds 600, so the slice cuts mid-anchor on essentially every world-built redraft. Impact: silently mangled continuity block in the re-rendered window → off-model renders billed at real money, with `storyboard.anchor` still looking intact in the record (the failure is invisible to every existing gate); likely blamed on the engine, then re-rejected — money-waste loop. Fix belongs at the boundary this file documents: either raise/remove the 600 cap in parseRedraft and re-verify anchor token coverage per redrafted shot (reuse the adversary's continuity axis), or export a `carriesAnchor(prompt, world)` helper from worldmodel.ts so both draft and redraft paths check the same law code-side.

- **[MEDIUM] validateWorld accepts duplicate character/set names — the selection contract's key is ambiguous** - `line 78` and `line 117` — CONFIRMED. What: characters need only a non-empty name; nothing enforces uniqueness across `characters` or `sets`. Trigger: brain emits two characters named "Vera" or two sets named "Rooftop" (common LLM behavior in ensemble casts). Impact: the downstream instruction "copy the RELEVANT character sheets CHARACTER-FOR-CHARACTER" (autopilot.ts:447) becomes ambiguous — two shots can each copy a different same-named sheet and every gate passes: names are the tokens the adversary's coverage check matches on, so identical names hide divergent constants. Silent subject drift across shots → wasted renders. Fix: reject duplicate names in `validateWorld` (a `Set` on `characters.map(c => name)` and `sets.map(s => s.name)`) — cheap, strict, and matches the module's refusal-not-heal doctrine; no call site depends on duplicates.

- **[LOW] Set materials validated twice — name-twin drift hazard** - `line 120` and `line 135` — CONFIRMED. `strList(st.materials, ...)` runs once for validation and again for extraction; idempotent today, but the two call sites will drift if one is edited (the exact duplicated-logic class the project keeps hitting). Fix: capture `const materials = strList(...)` once at line 120 and reuse.

## Missing safeguards
- No selection-integrity validator: ruling 42 ("the prompt selects, never invents") has no code teeth — nothing checks that storyboard shots reference only built characters/sets. The adversary checks anchor⊆prompt coverage (one direction); a shot inventing an unbuilt character passes every gate. A `validateSelection(world, storyboard)` beside `validateWorld` would close it.
- No size budget on `compileAnchor` (`line 147`): the anchor is mandated verbatim into every prompt and per-shot copies must embed full sheets; with ensemble worlds the block grows unbounded — the project's token-ceiling-degeneration class. No cap, no warning, no telemetry (PLAUSIBLE — brain output ceilings not verified here, but the redraft 600-char slice already demonstrates the collision).
- `num()` hardcodes `v > 0` (`line 64`): correct for heightCm, but as the file's only numeric gate it will silently refuse any future zero-valid numeric field. Consider a bounds-arg.
- Window-redraft path has no re-judgment hook: this file's `withWorldAnchor` covers storyboard replacement only; nothing in the module's surface lets the redraft path (vite.film.ts:1933) re-establish the anchor law it documents — the HIGH finding above is the concrete instance.
