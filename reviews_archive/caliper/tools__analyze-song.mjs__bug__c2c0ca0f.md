### Review

## Verdict
Not production-safe as a data source. The happy path works (verified end-to-end: the local `films/whole-world-ours/beats.json` it produced drives film-proof, contract intact — it writes `{...a, shotGrid}` at line 49 and consumers read `shotGrid[i].start/.end`, matching `ShotSlot {start, end, sectionIndex}` at src/film/analysis.ts:187). But the tool's primary failure paths are swallowed: a failed decode produces a plausible-looking beat table, a valid-shaped but empty JSON, and exit code 0; digital silence produces a confident phantom tempo. Its middleware twin (vite.film.ts:556) rejects on ffmpeg failure via `exec` — the CLI is the deficient twin.

## Bugs & vulnerabilities
- **[HIGH] ffmpeg failure swallowed — script emits garbage analysis with exit 0** - `line 21-27` — CONFIRMED. What: `dec.on("close", resolve)` ignores the exit code, and the `error` listener is attached only after `for await (const c of dec.stdout)` has drained, so an early `error` emission is missed. Trigger: any input ffmpeg cannot decode (non-audio file, truncated/corrupt mp3), or a partially-failed decode that exits nonzero after emitting partial PCM — the partial prefix is analyzed as if it were the whole song. Empirically reproduced with this exact pattern: non-audio input → ffmpeg exit 3199971767, 0 PCM bytes, promise resolves, no throw. Impact: the script prints "Duration 0.0s · tempo ? BPM · 0 beats · 1 sections · 0 shots" and — worse — writes a valid-shaped JSON (`{duration:0, tempo:null, beats:[], sections:[{start:0,end:0,...}], shotGrid:[]}`) and exits 0. ffmpeg's stderr is inherited so the console shows the error, but the tool's own artifacts contradict it, and the poisoned JSON flows downstream (film-proof.mjs:22 would then hit an empty `shotGrid` → its `findIndex` at line 38 returns -1 → deferred crash there). With ffmpeg missing from PATH entirely, the missed `error` event surfaces as an unhandled-'error' crash with a raw Node stack (also empirically confirmed). Fix: `dec.on("close", (c) => (c === 0 ? resolve() : reject(new Error(`ffmpeg exited ${c}`))))`, attach `on("error")` before consuming stdout, and gate output on sanity (`x.length === 0 || a.duration < 1` → error exit 1, no JSON write).
- **[MEDIUM] Digital silence yields a confident phantom tempo (~186 BPM) and phantom beat grid** - `line 27` (mechanism at src/film/analysis.ts:67-82) — CONFIRMED. What: `detectTempo` initializes `bestScore = -Infinity`; for an all-zero flux envelope every lag scores 0, so the FIRST candidate lag (minLag ≈ 186 BPM) wins and `null` is never returned. Empirically: 10 s of digital silence through `analyzePcm` → tempo 186.34, 31 beats. Trigger: quiet/no-onset inputs — ambience beds, a cappella stems, wrong file entirely. Impact: the CLI prints an authoritative-looking "186.3 BPM · N beats" table and `shotGrid` snaps boundaries to phantom beats (analysis.ts:190-198), seeding film timing with fiction. The CLI is the human-facing tool meant to be trusted for timing. Fix belongs in `detectTempo` (require `bestScore > ε`), but this tool should also refuse (e.g., median flux == 0 → exit with error). Cited both sides: emitter analysis.ts:81, consumer line 33/49.
- **[LOW] `--json` with a missing value silently writes nothing** - `line 16` — CONFIRMED by trace. `argv[indexOf("--json") + 1]` is `undefined` when the flag is last, so `jsonOut` is null and no file is written and no warning printed. The user sees a table, assumes success, then film-proof fails later on a missing/stale `beats.json`. Fix: explicit arity check, error if `--json` has no following argument.

## Missing safeguards
- No sanity gate between decode and analysis (non-empty samples, minimum duration) — the empty-input path (`analyzePcm` on 0 samples → duration 0, 1 section, 0 shots, no crash) is indistinguishable from success at the process level (always exit 0 on the failure path).
- No `--help`/usage exit distinguishes "file missing" (handled, line 12-15) from "file unreadable by ffmpeg" (not handled).
- The silence/low-onset phantom-tempo case (above) has no guard at this layer even though the tool is the checkpoint where a human could catch it.
